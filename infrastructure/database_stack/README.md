# LSMP Database Stack

This directory contains the infrastructure configurations, database schema definitions, and management scripts for the PostgreSQL and TimescaleDB database layer of the LSMP project.

---

## 📂 Directory Structure

```text
infrastructure/database_stack/
├── docker-compose.yml     # Docker Compose service definition
├── .env.example           # Environment variables template
└── schema.sql             # SQL script for database initialization
```

---

## 🏛 Component Architecture

The database stack consists of a single high-performance time-series database container:

| Component             | Container Name    | Default Ports | Description                                                                                      |
| :-------------------- | :---------------- | :------------ | :----------------------------------------------------------------------------------------------- |
| **TimescaleDB** | `lsmp-postgres` | `5432/tcp`  | PostgreSQL database with TimescaleDB extension for time-series logs and anomaly results storage. |

---

## 🏛 Database Schema Architecture

The database consists of **6 main tables** optimized for high-volume time-series security events and anomaly analysis.

### 1. Hypertables (TimescaleDB Optimized)

* **`log_event`**
  * **Description**: Stores raw, unstructured security alert logs forwarded from the Wazuh Manager. Includes `source_host` (client hostname) and `rule_id` (Wazuh rule ID) columns to support multi-client collections.
  * **TimescaleDB Config**: Partitioned by day (`timestamp`).
  * **Policies**:
    * **Compression**: Enabled after 7 days (segmentby `event_type`, `source_ip`, and `source_host` for optimal storage and query efficiency across clients).
    * **Retention**: Automatically purged after 90 days.
* **`feature_vectors`**
  * **Description**: Stores the computed 14 security feature vectors per IP within each sliding time window.
  * **TimescaleDB Config**: Partitioned by day (`window_start`).
  * **Policies**:
    * **Compression**: Enabled after 14 days (segmentby `src_ip` and `feature_version`).
    * **Retention**: Automatically purged after 180 days.
* **`anomaly_result`**
  * **Description**: Stores processed sliding windows of security features and anomaly inference scores generated by the AI model. Includes `feature_vector_id` linking logically back to `feature_vectors`.
  * **TimescaleDB Config**: Partitioned by week (`window_start`).
  * **Policies**:
    * **Compression**: Enabled after 30 days.
    * **Retention**: None (retained indefinitely to support future AI retraining datasets).

### 2. Regular Tables (Standard PostgreSQL)

* **`risk_score`**
  * **Description**: Stores the final aggregated risk priority score displayed on the analyst dashboard.
  * **Relationship**: Maintains a strict `1-to-1` relationship with `anomaly_result` via a `UNIQUE (anomaly_result_id)` constraint.
* **`attack_scenarios`**
  * **Description**: Stores cataloged, time-bounded metadata for attack scenarios executed during simulation runs (used for automated ground-truth labeling).
* **`evaluation_metrics`**
  * **Description**: Logs validation benchmarks (Precision, Recall, F1, latency, throughput, and system resource usage) across different AI pipeline configurations.

## 🚀 Deployment Guide

Follow these steps to configure and launch the database stack:

### 1. Prerequisites (Shared Network)

Before running the database container, you must create the shared external bridge network `lsmp_backend` if it does not already exist:

```bash
docker network create lsmp_backend
```

### 2. Environment Setup

Copy the environment template and set your credentials:

```bash
cp .env.example .env
```

Open the `.env` file and verify or change the default PostgreSQL credentials as needed.

### 3. Start the Database Stack

#### A. Run in the Foreground (for inspection/debugging)

```bash
docker compose up
```

#### B. Run in the Background (recommended for normal usage)

```bash
docker compose up -d
```

## 🛑 Teardown & Maintenance

To stop and preserve the volume states:

```bash
docker compose down
```

To fully stop, destroy containers, and wipe local Docker configurations/data:

```bash
docker compose down -v
```
